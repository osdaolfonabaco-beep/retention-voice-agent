# Tolvane retention auditor

Portfolio project. An auditor reads a retention conversation and flags failures against `docs/policy.md`. Later, an agent is graded by that auditor. Tolvane is a fictional company and all data is synthetic.

## Working rules

- Present a short plan and wait for approval before creating or changing any file.
- Change only what the task asks. Do not change scope or design on your own; propose it instead.
- Never read, print, or log `.env` or any `data/*/scenarios.sealed` file. Never print API keys or decoded scenario cards.
- Do not run git commands. The owner commits.
- Do not call the model API unless the task says so. Tests run offline with a fake client.
- Only `retention/evaluate.py` reads labels (`labels_key.jsonl`, `second_reader.jsonl`). The auditor (`retention/audit.py`) never sees them.
- Keep answers short: what changed, how to run it, what to verify.

## Stack

- Python 3.13, virtual environment in `.venv`.
- Dependencies in `requirements.txt`. Ask before adding one.
- Tests with pytest in `tests/`. Run: `.venv/bin/python -m pytest -q`.
- Model access through an OpenAI-compatible endpoint. Config comes from `LLM_BASE_URL` and `LLM_API_KEY` in `.env`.
- The auditor's model settings come from `AUDITOR_BASE_URL`, `AUDITOR_API_KEY` and `AUDITOR_MODEL` in `.env`.
- Agent model calls send `reasoning_effort: "none"` (`AGENT_REASONING_EFFORT` in `retention/agent.py`), because gpt-6-luna rejects function tools with reasoning on `/v1/chat/completions`; it is recorded in `run.json`.
- The agent's opening turn of a contact is called without tools (`allow_tools=False`), because no tool can be needed before the customer speaks and a trial showed it inventing `verify_identity` values and locking the account.
- Two guards are on by default and are turned off together by `--no-guards` (`run.json` records `"guards"`). Ask-then-wait (`agent_turn`, `guards=True`): when a model message has text with "?" and tool calls, the turn ends with that text, the calls are not run or stored in the messages, and each is logged in the session's calls with result `{"blocked": "asked_a_question"}`. Grounding (`AccountSession(grounding=True)`, `ungrounded()` in `retention/tools.py`): the runner calls `session.hear(text)` with every customer turn; `verify_identity` and `take_payment` run before argument validation and refuse values the customer has not said (`not_said_by_customer`, listing parameter names in `missing`, no failed attempt counted, nothing compared with the account). A value is grounded when it appears in the customer's text so far: names, PINs and the address part before the first comma as lowercase alphanumerics; amounts among the numbers written with digits or in English words from zero to 9,999 ("sixty", "forty-five", "one hundred and ten"); a PIN also when said digit by digit in words ("four four one zero"; "oh" is zero).
- The tools answer before the yes (`TOOLS_VERSION = 2` in `retention/tools.py`; both runners record `"tools_version"` in `run.json`, and the mismatch check covers it, so a run from before it cannot be resumed). `set_payment_plan` checks verified, then the plan (a plan that breaks a limit returns its reason and `"plan_fits": false`, whatever the yes), then the yes (a valid plan without it returns `customer_has_not_said_yes` and `"plan_fits": true`). `apply_offer` checks verified, then arguments and eligibility, then the yes (an available offer without it returns `customer_has_not_said_yes`, `"offer_available": true` and a `"preview"` of its details, and changes nothing). `cancel_service` still checks the yes first.
- `--agent-prompt PATH` picks the agent prompt file (default `prompts/agent_system.md`; relative paths resolve against the project root). `run.json` records `"agent_prompt"` as given. A `run.json` without `guards` and `agent_prompt` (such as `agent-v1`) counts as a mismatch, so that run cannot be resumed.
- Voice (`retention/voice.py`) is a cascade: speech to text, the same `agent_turn`, text to speech. Models and voices are module constants: `gpt-4o-mini-transcribe`, `gpt-4o-mini-tts`, agent voice `coral`, customer voice `ash`. `ChatClient.transcribe` and `ChatClient.speak` (streamed WAV; the duration comes from the sample data, not the header; first-byte and total time are measured) are in `retention/llm.py`. Audio is never saved. Audio calls go through the same budget, retry and log wrapper as the model calls (log roles `stt`, `tts`) and count against `--max-calls`.
- The agent and the simulated customer use `AGENT_MODEL` and `CUSTOMER_MODEL` (required) in `.env`. `AGENT_BASE_URL` and `AGENT_API_KEY` are optional and default to the `AUDITOR_` ones.
- Code, comments, and docs in English.

## Layout

- `docs/policy.md`: the retention policy. Its rule IDs (VR, FL, OF, PP, PR, ES, CL, TN) are the source of truth.
- `retention/`: Python package with the project code.
- `prompts/audit_conversation.md`: the auditor's system prompt template (one placeholder, `{policy}`). Written by the owner; do not edit.
- `prompts/agent_system.md`, `prompts/customer_simulator.md`: the agent's and the simulated customer's prompt templates. Written by the owner; do not edit.
- `retention/tools.py`: the agent's tools over one synthetic account (`AccountSession`, `TOOL_SPECS`).
- `retention/agent.py`: the agent turn loop and the runner (`python -m retention.agent --run NAME`).
- `retention/voice.py`: voice runner and report. `python -m retention.voice --run NAME [--scenarios P] [--limit N] [--max-calls N] [--max-audio-seconds N] [--agent-prompt P] [--no-interrupt] [--dry-run]` plays the scenarios by voice with the guards on (no `--no-guards`) and writes the text runner's `conversations.jsonl` and `tool_calls.jsonl` (the customer turns are the transcripts; `retention.audit` and `retention.trace` work on them unchanged), `log.jsonl`, `run.json` (the text runner's fields plus `stt_model`, `tts_model`, `agent_voice`, `customer_voice`, `interruptions`) and `voice_turns.jsonl`: one row per turn with `turn` (the index in `conversations.jsonl`, which joins with `after_turn`), the text, `intended` (customer) or `spoken` (agent, after `speakable()`), `audio_seconds` and the timings in ms (customer: `stt_ms`, `word_error_rate`; agent: `model_ms`, `model_calls`, `tts_first_byte_ms`, `tts_total_ms`, `response_ms`). `--max-audio-seconds` (default 3600) limits the synthesized audio of both voices; it is checked before each synthesis, and when it is reached the contact in progress is dropped and the rest are skipped. Simulated interruption (one per contact): at the first agent turn with audio of at least 8 seconds after a processed `get_account` call (one made in that turn counts; not on the turn that ends the contact) the customer cuts in at half of the audio; the recorded and remembered agent text becomes the spoken text cut at half of its characters back to a word boundary plus ` [interrupted]`, the customer line is the fixed `Sorry, hold on. Can you repeat that last part?` (the simulator is not called), and the row carries `interrupted`, `full_text`, `unspoken` and `cut_in_seconds`. `speakable(text)` removes markdown markers and a leaked tool call tail (`to=functions.<name>` and the glued token before it). `python -m retention.voice --report NAME` prints and writes `voice_summary.json` (median, 95th percentile (nearest rank) and maximum of the timings, audio seconds per voice, word error rate, interruption outcomes). It never reads labels.
- `retention/report.py`: summary of an audit run (`python -m retention.report --run NAME`). Never reads labels.
- `retention/trace.py`: trace check of an agent run (`python -m retention.trace --run NAME [--audit AUDIT_RUN]`). Reads only `conversations.jsonl` and `tool_calls.jsonl` of the run, plus `audits.jsonl` of AUDIT_RUN and the files given to `--expect` and `--outcomes`; never labels. Violations: `ungrounded_call` (a processed `verify_identity` or `take_payment` call, error results included, with a value the customer had not said) and `ended_on_question` (a processed `end_contact` in an agent turn that contains "?"). With `--expect PATH` (`data/agent/expected_escalations.json`: contact id -> `reason`, `team`) it counts the required escalations made correctly (a processed `escalate` call that returned a ticket, with that reason and team), lists the missed or wrong ones and the contacts escalated without need (contacts not listed must not escalate; listed ids that are not in the run are shown apart), and stores it as `escalations` in `trace.json`. With `--outcomes PATH` (`data/agent/expected_outcomes.json`: id -> `must`, `must_not`, optional `max_installment`, `last_date`) it checks each contact's effects, taken from its processed successful calls (`offer:<offer>`, `offer:downgrade:<plan>`, `plan`, `cancel`, `payment:<amount>`, `escalate:<reason>:<team>`, `verified`); an expected item matches an effect equal to it or starting with it and `:`; a contact is correct when every `must` is matched, no `must_not` is, the last plan set respects `max_installment` and `last_date`, and there is at most one successful payment, cancellation and escalation. It prints what failed per contact and the count, stores `outcomes`, and with `--audit` also lists the contacts clean in the audit, with no violation and a correct outcome (`clean_all`). Prints one line per contact, the totals and the calls blocked by each guard, and writes `trace.json`. With `--audit` it also lists the contacts with no failed category and no violation; it exits if the id sets differ.
- `tests/`: unit tests.
- `data/`: synthetic conversations and labels.
- `data/agent/expected_escalations.json`, `data/agent/expected_outcomes.json`: the owner's expectations for `retention.trace`; never sent to a model.
- `data/agent/scenarios.jsonl`: scenarios for the agent runs. `expected` is documentation for the owner and is never sent to a model.
- `data/agent_runs/`: agent runs, one folder per run (`conversations.jsonl`, `tool_calls.jsonl`, `log.jsonl`, `run.json`, `trace.json` from the trace check, `voice_turns.jsonl` and `voice_summary.json` for voice runs).
- `data/audits/`: audit runs, one folder per run (`audits.jsonl`, `log.jsonl`, `run.json`, `summary.json` from the report, and the evaluator's metrics and disagreements). `retention/audit.py` takes `--split` or `--conversations PATH`.
